# T0910 闫昱硕：结论、置信度与证据边界复核

> 依据：2026-09-10《MCP 与真实 Agent 接入信息逐项索取责任表》（闫昱硕：复核结论、置信度和证据强弱边界）。
> 对象：杨景凡《T0905-07 深度调查 Agent 接入信息说明》及实现 `agent.py` / `knowledge.py` / `deep_agent_bridge.py`。
> 基准规则：本目录《证据强弱与结论上限规则》第 2 节（三档门禁上限）、第 5 节（结论上限三个固定约束）。

## 一、复核结论（总）

杨景凡的输入/输出契约与「知识隔离」（guarded 三档门禁）方向正确：工具调用记录 `tool_call_records` 与调查步骤 `investigation_steps` 已由代码侧强制防编造；降级报告也遵守「无证据不出结论、攻击链置未知、触发人工接管」。

当前主要缺口是：**结论、置信度、关键证据、攻击链仍由 LLM 自由生成，未与三档 `gate_decision` 的结论上限做代码级联动**，目前只靠 `SYSTEM_PROMPT` 约定。以下是逐项复核意见，作为进入真实平台联调前的补齐项。

## 二、逐项复核

### 2.1 conclusion（结论）

- ✅ 已满足：`SYSTEM_PROMPT` 明令「绝不编造证据」「工具失败/为空时如实记录数据不可得」；`_parse_report` 在**没有任何 success/partial 工具记录**时强制走降级报告，禁止基于未验证信息生成结论。
- ⚠️ 需补：`conclusion` 文本未与三档门禁联动。`weak_signal` 案仍可能被 LLM 写成「确认攻击/已植入」。建议契约明确结论只能落在**输入已观察到的证据**，并按三档限定措辞：
  - `in_scope`：可写「高风险、建议处置」，但不得写输入中没有的植入/执行/持久化/载荷；
  - `weak_signal`：只能写「疑似/证据不足，建议核查」，不得确认；
  - `out_of_scope`：只能写「非 WebShell / 转交其他攻击链」。
- ⚠️ 需补：不得把知识库说明写成事实结论。知识命中目前只说明「可查什么」，结论字段未做「知识≠证据」的强制校验。

### 2.2 confidence（置信度）

- ✅ 已满足：0~1 数值；桥接层 `_confidence` 做 [0,1] 截断，非数值回退为上游研判置信度。
- ⚠️ 需补：缺少「区间 / 缺证据 / 不可比较」说明，也未与证据强弱联动——弱信号/域外案可能被 LLM 给出偏高置信度。建议：
  - confidence 必须注明依据（事件证据 vs 通用知识）；
  - 证据不足/域外时不得给出高置信度，与 `gate_decision` 联动给出上限；
  - 不写无依据的固定高分（沿用「不宣称百分比收益」限制）。

### 2.3 key_evidence（关键证据）

- ✅ 已满足：降级报告 `_fallback_report` 中 `key_evidence` 仅取 `event.evidence` + 成功/部分成功工具输出（截断 200 字符）；知识 `evidence_refs` 单独进入 `evidence_source`（标「知识包引用:」），未混入 `key_evidence`。
- ⚠️ 需补：正常路径（`_parse_report`）下 `key_evidence` 由 LLM 生成，代码未校验「只引用事件/工具证据、不含通用知识」。建议代码侧对知识命中做过滤或标注——知识引用一律降级为 `evidence_source`，不得进 `key_evidence`。

### 2.4 attack_chain（攻击链）

- ✅ 已满足：降级报告 `attack_chain="未知"`（无证据不补全）。
- ⚠️ 需补：正常路径 `attack_chain` 由 LLM 生成，无「无证据不得补全攻击链」的代码校验。建议契约明确：攻击链只能由输入/工具证据支撑，缺环节写「未知/待核」，不得用知识模板补全。

### 2.5 evidence_refs / evidence_source（证据引用）

- ✅ 已满足：知识 `evidence_refs` 与事件证据分栏（`evidence_source` vs `key_evidence`）；`knowledge_query` 命中的 `evidence_refs` 单独记录，不并入事件证据。
- ⚠️ 需补：桥接层 `_to_domain_report` 未把 `evidence_source` 带入主链领域模型（`key_evidence_refs` 只取 `key_evidence`，`evidence_relations` 只取 `attack_chain`），导致「知识引用 vs 事件证据」的区分在下游丢失。建议主链保留 `evidence_source` 并标注来源类型（知识包引用 / 来源工具）。

### 2.6 可测样例（按责任表 3.7 复核）

- 预期 `conclusion / confidence 范围 / key_evidence` 需符合三档结论上限；
- 预期 `key_evidence` 必须能追溯到输入或工具结果（陈敏核对输入来源）；
- 至少补一个非 WebShell 负向样例，验证**不会套用 WebShell 知识**（对应 `out_of_scope`）。

## 三、结论上限联动（总体要求）

建议在 Agent 输出契约中显式加入 `gate_decision` 结论上限，与《证据强弱与结论上限规则》第 2/5 节对齐：

- 知识命中（任何强度）不改变结论强度；
- 单一弱信号不得升级为确认级；
- 工具失败/空集/权限不足保留为证据缺口，并触发人工接管；
- 结论只复述输入已观察证据，不新增输入中不存在的植入/执行/持久化/最终载荷。

## 四、复核结论

同意杨景凡的输入/输出契约与三档门禁作为**内部合同基线**；在补齐上述「结论上限联动 + 知识≠证据 + confidence 口径 + attack_chain 无证据不补全 + evidence_source 主链保留」五处代码级约束后，方可进入真实平台联调。当前不阻塞 Mock/离线路径。
