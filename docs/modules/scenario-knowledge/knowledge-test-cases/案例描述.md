# 知识评测样本（6个案例）

> 用途：基于Agent实际使用的`SecurityEventInput`顶层JSON格式设计测试用例，用于验证知识检索命中和Agent消费边界。
>
> 数据性质：6案均为公开材料改编或通用条件构造的synthetic评测输入，不是真实XDR响应、真实平台事件或运行A/运行B证据。详见[来源矩阵](./来源矩阵.md)。

## 用例详细说明


### TC-KNOWLEDGE-001：IIS WebShell（UpdateChecker.aspx）

| 字段 | 内容 |
|---|---|
| **类别** | 正向变体 |
| **来源** | https://www.fortinet.com/blog/threat-research/in-depth-analysis-of-an-obfuscated-web-shell-script （FortiGuard Labs于2025年7月发布的分析报告） |
| **简介** | FortiGuard Labs分析：UpdateChecker.aspx WebShell（2025），分析部署在Microsoft IIS服务器上的混淆WebShell，包括Unicode编码和加密混淆技术、JSON命令结构及三大模块功能 |
| **攻击特征** | ASPX页面，Unicode编码+加密混淆；HTTP POST触发，请求头`application/octet-stream`；命令通过Base64编码的AES加密数据传递；支持信息收集、文件管理、命令执行三大模块 |
| **输入事件** | 见 `case1.json` |
| **预期查询词** | `["WebShell攻击原理", "WebShell证据检查清单"]` |
| **预期命中知识** | `webshell-knowledge.md §1.2 攻击原理`（WebShell定义与隐蔽通信特征）；`webshell-knowledge.md §3 Agent证据检查清单`（文件系统检查、Web日志异常请求检查） |
| **预期报告变化** | 在该synthetic输入下识别WebShell风险和加密HTTP通信线索；检查是否命中攻击原理/证据检查清单、是否在报告中留下知识引用、是否避免编造攻击者和初始访问路径 |
| **禁止结论** | 不得把该输入写成真实XDR事件；不得仅凭AES与`application/octet-stream`确认是冰蝎Behinder；不得断言攻击者身份、C2服务器或无日志支撑的初始访问路径 |


### TC-KNOWLEDGE-002：Godzilla WebShell（PassiveNeuron活动）

| 字段 | 内容 |
|---|---|
| **类别** | 正向变体 |
| **来源** | https://securelist.com/passiveneuron-campaign-with-apt-implants-and-cobalt-strike/117745/ （卡巴斯基官方研究团队GReAT发布详细技术报告的网站） |
| **简介** | PassiveNeuron间谍活动（2025）：利用暴露的ASP.NET MachineKey部署Godzilla WebShell；卡巴斯基于2024年底首次发现，主要针对亚洲、非洲和拉丁美洲的政府、金融和工业部门 |
| **攻击特征** | 利用暴露/重复使用的MachineKey（ValidationKey/DecryptionKey）通过`_VIEWSTATE`反序列化执行任意命令；部署Godzilla家族WebShell（1.aspx）；进一步部署TOLLBOOTH持久化模块和内核驱动Rootkit隐藏痕迹 |
| **输入事件** | 见 `case2.json` |
| **预期查询词** | `["哥斯拉 流量特征"]` |
| **预期命中知识** | `webshell-knowledge.md §2.2 主流管理工具与流量特征（哥斯拉行）`（AES/RSA强加密、分块传输特征） |
| **预期报告变化** | 在该synthetic输入下识别Godzilla WebShell线索；标注输入中给出的内核驱动和进程隐藏信号；建议检查MachineKey配置和持久化模块；上述内容不能伪装成当前知识包命中 |
| **禁止结论** | 不得把该输入写成真实XDR事件；不得无直接来源映射为CVE-2020-0688；不得断言攻击者身份或已完全清除后门 |

| **攻击特征** | 当前只把PHP WebShell、加密命令和JSON通信作为评测输入信号；RSA细节、感染数量和时间戳修改在原始来源补齐前不得写成已独立核实事实 |

## 执行说明

- **运行方式**：将 `case1~6.json` 逐个传入Agent，观察Agent是否返回结果以及返回的知识是否被正确检索或写入调查报告。
- **判断标准**：
  - **正向变体（TC-001~003）**：预期查询词命中目标知识条目（检索通过），且知识被正确写入报告（Agent实际消费），视为"通过"
  - **证据不足（TC-004~005）**：Agent输出"证据不足/需要人工接管"视为"通过"
  - **纯负向对照（TC-006）**：不调用WebShell知识、不在报告中增加WebShell事实，视为"通过"
- **注意事项**：正向变体中"检索通过"和"Agent实际消费"两个环节均需验证；证据不足案例不得编造结论；负向案例出现WebShell知识命中或WebShell结论即失败。
