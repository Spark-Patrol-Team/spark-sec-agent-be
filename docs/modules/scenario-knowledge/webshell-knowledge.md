>
> 使用方法：Agent根据当前调查阶段和证据缺口，从以下章节中按需检索对应内容。
>
> 使用约定：
>
> - Agent在调用本知识包时，调用参数应包含关键词（如 `WebShell攻击原理`、`WebShell处置建议`）。
> - 当前知识材料供调查 Agent 人工加载或后续导入知识库。
> - 当前版本面向最小纵向链路，覆盖WebShell场景的核心调查需求。

## 1. 攻击概述

### 1.1 攻击名称

- **WebShell（网页后门）** —— MITRE ATT&CK 技术编号：T1505.003
- 相关术语：一句话木马（如 `<?php @eval($_POST['cmd']); ?>`）、大马（功能完整型）、小马（功能单一型）、内存马（无文件落地型）

### 1.2 攻击原理（Agent回答“这是什么攻击”时使用）

WebShell 是被植入 Web 服务器的恶意脚本。攻击者通过 HTTP/HTTPS 协议与其通信，获得与 Web 服务器进程同权限的远程命令执行能力。

核心特征：

- 通信流量混入正常 Web 流量（80/443 端口），较容易绕过传统边界防火墙；
- 不会产生账号登录类系统日志；
- 若服务器开启审计，执行命令仍会留下系统审计痕迹，痕迹主要留存于Web访问日志；
- WebShell 常利用文件上传漏洞、远程代码执行漏洞或服务器配置错误实现植入。

## 2. Agent 可检索的知识条目

### 2.1 攻击特征速查表

Agent在调查过程中可通过传入关键词（如 `WebShell攻击特征`）进行检索，返回以下参考信息：

| 攻击类型            | 关键特征                                             | 调查方向              |
| :------------------ | :--------------------------------------------------- | :-------------------- |
| **WebShell 上传**   | 双扩展名、上传路径含 `/uploads/`、文件内容含 `eval(` | 检查文件系统、Web日志 |
| **WebShell 通信**   | POST 请求参数 `z0`/`z1`/`z2`、UA固定、Base64编码     | 检查Web日志、网络连接 |
| **WebShell 持久化** | crontab新增、SSH公钥新增、注册表Run项新增            | 检查计划任务、启动项  |

[引用来源：MITRE ATT&CK T1505.003；NSA/CISA 联合报告]

### 2.2 主流管理工具与流量特征

Agent在调查过程中可通过传入工具名称（如 `中国菜刀 流量特征`）进行检索，需要时返回以下参考信息。

⚠️ 下述均为各WebShell工具【默认配置】下的流量特征。实际攻防场景中，攻击者可通过修改客户端配置等方式绕过。因此，本节内容仅作为可疑启发线索，不可作为唯一判定证据。建议出现表中任一特征，应标记为“可疑”，并进入下一轮调查以获取更多证据。

| 工具                     | 流量特征                                                     | 启发式识别要点                                               |
| ------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **中国菜刀（Chopper）**  | POST 请求参数固定为 `z0`、`z1`、`z2`；数据经 Base64 编码；默认User‑Agent常为 `Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1)` | 出现固定参数名 `z0`/`z1`/`z2` 组合 + 默认 UA 时，标记为可疑；需排除已知业务系统误报； |
| **蚁剑（AntSword）**     | 默认 UA 中常含 `AntSword` 关键字；payload 常经过混淆/编码    | UA 中出现 `AntSword` 或路径含可疑命令接口时，标记为可疑；注意攻击者可自定义UA绕过； |
| **冰蝎（Behinder）**     | 默认使用 AES 动态加密通信；Content‑Type 常见为 `application/octet-stream`；支持 WebSocket 长连接 | 出现二进制加密流 + WebSocket 长连接，且无业务合理解释时，标记为可疑；需要更多上下文确认 |
| **哥斯拉（Godzilla）**   | 默认使用 AES/RSA 强加密；参数名常见为随机生成（如 `x1`、`y2`）；支持分块传输（Transfer‑Encoding: chunked） | 分块传输 + 随机参数名 + 强加密特征组合出现时，标记为可疑；单独出现分块传输可能为正常业务 |
| **Weevely**              | HTTP 请求中常包含 `Weevely` 或 `wv` 字段；常通过 `?` 传递加密参数；默认 UA 常为 `Weevely` 或随机标识；支持自定义混淆及模块扩展 | 请求中出现 `Weevely`/`wv` 字段或固定 UA 时，标记为可疑；攻击者可通过模块扩展自定义混淆，需结合payload分析 |
| **隐蔽通道（DNS/ICMP）** | 常使用 DNS 隧道或 ICMP 协议进行数据外传；DNS 请求中常见长编码子域名；ICMP 数据包 payload 部分常见异常数据 | 出现长编码DNS子域名（如 `abcd1234.xxx.com`）或异常ICMP payload时，标记为可疑；需结合外传目的IP和流量基线判断 |

## 3. Agent 证据检查清单

Agent 在调查 WebShell 事件时，应依次检查以下证据项，并在调查报告中记录检查结果：

| 序号 | 检查项                                                 | 证据来源     | 预期发现                             |
| :--- | :----------------------------------------------------- | :----------- | :----------------------------------- |
| 1    | 目标 Web 服务器的 Web 目录下是否存在新增的可疑脚本文件 | 文件系统检查 | 如 `shell.php`、`cmd.jsp` 等异常文件 |
| 2    | 该文件是否具有双扩展名或与业务无关的命名               | 文件系统检查 | 如 `image.jpg.php`、`test.aspx`      |
| 3    | Web 访问日志中是否存在异常 POST 请求或固定参数         | Web 日志分析 | 如 `z0=`、`z1=` 等菜刀特征           |
| 4    | Web 服务器进程是否启动了命令行程序                     | 进程监控     | 如 `w3wp.exe` 启动 `cmd.exe`         |
| 5    | 服务器是否存在异常的对外网络连接                       | 网络监控     | 如非业务时段的外连                   |

[引用来源：NSA/CISA 联合报告；CISA Eliminate Web Shells (CM0106)]

## 4. Agent 处置建议模板

Agent 输出调查报告时，如需生成处置建议，应参照以下流程引用：

参照 **CISA《Eliminate Web Shells》(CM0106)** 消除指南，建议按以下顺序处置：

1. **隔离（Isolate）**：将受感染的 Web 服务器隔离，减少横向移动的可能性；
2. **保全证据（Preserve Artifacts）**：保留磁盘/内存镜像，以及操作系统、Web 应用、访问、错误、WAF、反向代理、CDN、DMZ 防火墙和数据库等各类日志；
3. **删除 WebShell（Delete the web shell）**；
4. **修改密码**：修改 Web 管理员、数据库用户、托管账户和远程访问（FTP、SSH 等）的密码；
5. **调查根本原因**：调查导致入侵的底层漏洞；
6. **从干净备份恢复（Restore from clean backup）**；
7. **修复和加固**：通过打补丁和加固 Web 应用及 Web 服务器进行修复；

[引用来源：CISA Eliminate Web Shells (CM0106) - "Eliminating Web Shells" 章节]

## 5. Agent 停止条件与人工接管规则

### 5.1 停止条件

满足以下任意条件即停止调查：

1. **证据足够**：已获得支持明确调查结论的关键证据；
2. **达到最大步骤**：调查步骤达到预设上限（MVP阶段建议 `step >= 3`）；
3. **工具无法获得数据**：XDR 查询失败、数据为空、权限不足；

### 5.2 人工接管条件

以下情况触发人工接管：

- 高风险事件 + 关键证据不足 + 关键工具调用失败；
- 调查结果存在明显冲突；
- 涉及高风险处置动作且缺少审批；

Agent 在上述情况下应输出“**证据不足，需要人工接管**”，不得自行编造结果。
