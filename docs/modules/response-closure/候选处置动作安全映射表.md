# 候选处置动作安全映射表

## 一、文档定位

本文档对应 `T0827-08 肖迎春：平台处置能力核验与 Mock 安全边界` 第二项任务，用于在《平台处置能力核验表》的基础上，整理候选处置动作的安全控制设计。

本文档回答以下问题：

- 候选动作具有什么处置语义；
- 动作默认属于什么风险等级；
- 是否允许自动执行，何时必须人工审批；
- 应调用什么类型的对象；
- 调用成功后应如何独立验证；
- 超时、失败、部分成功和重复请求如何处理；
- 是否存在可接受的反向动作或回滚路径；
- 当前平台证据是否足以支持真实调用。

本文档是安全映射和 MVP 控制基线，不是 XDR 的最终 API 契约。平台真实 `tool_name`、`action_name`、请求参数、返回字段、错误码、超时语义和生效查询接口，仍需通过 OpenAPI、MCP 或实机最小调用进一步确认。

## 三、安全控制枚举

### 3.1 风险等级

| 等级 | 含义 | 默认控制 |
| --- | --- | --- |
| `LOW` | 不直接改变网络、主机或文件安全状态，影响范围可控 | 满足白名单、限频和参数校验后可自动执行；异常时进入人工处理 |
| `MEDIUM` | 可能改变单个告警、事件或单个网络对象的处置状态 | 默认人工审批；仅在明确限定目标、范围和时效后考虑自动执行 |
| `HIGH` | 可能影响主机可用性、文件运行或业务连接 | 必须人工审批；必须有独立验证和明确反向动作或人工恢复方案 |
| `CRITICAL` | 可能造成大范围业务中断、降低安全防护或无法可靠恢复 | 禁止自动执行；只允许建议、审批后人工执行或人工接管 |

风险等级是默认等级，不是对所有场景的固定判定。以下情况应至少上调一级：

- 目标为生产核心资产、域控、数据库、核心业务入口或未知资产；
- 目标数量超过单目标阈值；
- 动作没有有效期、范围约束或可验证的反向动作；
- 处置依据只有单条低置信度告警；
- 目标命中资产白名单、业务例外或高价值服务；
- 平台返回部分成功、状态不明或无法查询生效证据。

### 3.2 执行策略

| 策略 | 含义 |
| --- | --- |
| `AUTO_ALLOWED` | 仅在确定性规则、参数校验、白名单和限频均通过时允许自动执行 |
| `APPROVAL_REQUIRED` | 进入 `APPROVAL_REQUIRED`，审批通过后才能调用下游工具 |
| `HUMAN_ONLY` | 系统只生成建议、工单或执行草案，不自动调用真实处置工具 |
| `FORBIDDEN` | 当前边界内不得执行；如需处理必须由负责人重新确认范围和授权 |

`AUTO_ALLOWED` 只表示安全控制上允许进入自动路径，不表示当前 XDR 环境已经具备真实调用条件。

### 3.3 结果语义

处置结果必须至少区分以下层次：

1. `accepted`：调用请求被平台或适配器接收；
2. `executed`：平台返回动作已执行或已记录；
3. `effective`：独立查询或外部行为证据证明处置实际生效；
4. `ineffective`：有证据表明处置未生效；
5. `unknown`：无法确认动作是否生效；
6. `partial_success`：多个目标或多个动作中只有部分完成。

不能用 `ToolResult.status=success` 直接推导 `VerificationStatus.EFFECTIVE`。当前代码已经通过 `response_verify -> query_action_status` 区分执行和验证；真实适配器接入后仍应保留这一区分。

## 五、逐项安全映射

### 5.1 通知

| 项目 | 安全控制设计 |
| --- | --- |
| 动作语义 | 将处置建议、审批请求、失败告警、验证结果或人工接管请求发送给指定接收者 |
| 允许自动执行 | 允许。仅限已配置接收者、模板和频率限制的通知，不得由模型自由扩展收件人 |
| 审批要求 | 单纯通知通常不需要审批；涉及敏感事件内容、外部收件人或大范围群发时转人工确认 |
| 目标约束 | 接收者必须来自配置白名单；通知正文使用脱敏后的事件摘要和证据引用 |
| 预期结果 | 平台返回发送请求结果，并产生消息或通知记录 |
| 独立验证 | 查询发送记录、消息状态或通知审计记录；无法确认送达时标记为 `unknown` |
| 失败处理 | 参数校验、收件人无效不自动重试；明确可重试的网络错误最多按统一重试策略处理 |
| 回滚/反向动作 | 通知通常不可回滚；错误通知应通过补充通知纠正，并保留审计记录 |
| 人工接管 | 收件人不明、敏感信息疑似泄露、连续发送失败或通知内容与事件不一致时转人工 |

### 5.2 告警/事件状态调整

| 项目 | 安全控制设计 |
| --- | --- |
| 动作语义 | 调整告警或安全事件的处置状态，反映分诊、调查、处置或关闭阶段 |
| 允许自动执行 | 仅允许有限状态推进，例如 `new -> triaged` 或 `triaged -> investigating`；不得自动关闭未完成验证的事件 |
| 审批要求 | `contained`、`closed` 或等价终态调整必须具备独立验证证据；当前建议人工审批 |
| 目标约束 | 只允许调整与当前 `event_id` 关联的对象；禁止批量修改未知范围对象 |
| 预期结果 | 返回目标对象 ID、调整前状态、调整后状态和平台记录引用 |
| 独立验证 | 重新查询告警/事件详情，确认状态持久化；同步检查操作日志 |
| 失败处理 | 状态冲突时重新读取最新状态，不覆盖其他操作者的更新；权限失败直接转人工 |
| 回滚/反向动作 | 仅允许回到上一个已审计状态，且需避免掩盖真实处置失败 |
| 人工接管 | 状态机冲突、平台状态未知、目标不存在或需要关闭事件时转人工 |

### 5.3 IP 阻断与解封

| 项目 | IP 阻断 | IP 解封 |
| --- | --- | --- |
| 动作语义 | 在具备联动能力的网络或终端设备上阻断目标 IP | 移除由本系统创建的 IP 阻断 |
| 默认风险 | `MEDIUM`；生产核心网段、批量目标或长期封禁上调为 `HIGH/CRITICAL` | `HIGH` |
| 执行策略 | `APPROVAL_REQUIRED` | `APPROVAL_REQUIRED` |
| 前置检查 | IP 格式、内外网属性、资产归属、威胁证据、白名单、目标数量、有效期和重复规则 | 必须存在本系统创建的原始封禁记录、原审批记录和原规则引用 |
| 禁止条件 | 命中核心资产白名单、目标范围不明、无有效期、来源仅为低置信度单条告警 | 找不到原始记录、封禁由其他系统创建、解封可能恢复持续攻击 |
| 预期调用结果 | 返回规则或动作 ID、目标、设备、状态和有效期 | 返回被移除的规则或动作 ID及原始关联记录 |
| 独立验证 | 查询平台封禁对象和规则状态；在专用测试目标上进行受控连通性验证 | 查询封禁对象已移除或已失效，并确认业务连通性恢复符合预期 |
| 失败处理 | 超时先查询规则状态，不能在状态不明时直接重复封禁；部分设备成功时标记 `partial_success` | 状态不明时保持原封禁，不自动反复解封 |
| 回滚/反向动作 | 通过带原始引用的解封动作回滚；回滚也需要审批 | 如解封后发现风险未消失，重新进入审批流程，不自动恢复未知规则 |
| 人工接管 | 目标归属不清、白名单冲突、平台设备资源不足、无法确认生效或跨设备部分成功 | 业务恢复异常、原规则不完整或存在其他系统同类封禁 |

当前环境中，IP 封禁页面和模板入口已确认，但缺少可测 AF/防火墙资源；因此不得将上述映射直接转换为真实封禁调用。

### 5.4 域名拦截与解除拦截

| 项目 | 安全控制设计 |
| --- | --- |
| 动作语义 | 阻断终端或网络设备访问指定域名；反向动作移除本系统创建的拦截规则 |
| 默认风险 | 拦截为 `MEDIUM`；解除拦截为 `HIGH`；通配符、顶级域名或大范围规则上调为 `CRITICAL` |
| 执行策略 | 两者均为 `APPROVAL_REQUIRED`；大范围规则为 `HUMAN_ONLY` |
| 前置检查 | 域名规范化、解析结果、通配符范围、业务白名单、恶意证据、有效期和目标设备 |
| 预期调用结果 | 返回规则 ID、规范化域名、设备范围、状态和有效期 |
| 独立验证 | 查询平台规则状态，并在专用终端或测试网络执行受控 DNS/HTTP 访问验证 |
| 失败处理 | 超时先查询规则；设备间结果不一致时标记 `partial_success`，禁止将其汇总为全局生效 |
| 回滚/反向动作 | 使用原规则 ID解除拦截；禁止按域名重新搜索后盲目删除同名规则 |
| 人工接管 | 域名为共享基础设施、CDN、云服务域名、通配符域名，或无法确定业务影响时转人工 |

当前环境中，域名拦截页面和预案模板入口已确认，但真实联动设备和生效证据未验证。

### 5.5 主机隔离与解隔离

| 项目 | 主机隔离 | 主机解隔离 |
| --- | --- | --- |
| 动作语义 | 限制主机网络或通信能力，降低威胁继续扩散风险 | 恢复已隔离主机的正常网络能力 |
| 默认风险 | `HIGH` | `HIGH` |
| 执行策略 | `APPROVAL_REQUIRED` | `APPROVAL_REQUIRED` |
| 前置检查 | 主机唯一标识、在线状态、资产重要性、当前登录用户、业务维护窗口、隔离影响和退出条件 | 必须存在隔离记录、验证结论和恢复审批；不得仅因调用成功解隔离 |
| 预期调用结果 | 返回主机标识、隔离状态、设备来源和动作记录 | 返回主机标识、解除状态和原隔离记录引用 |
| 独立验证 | 查询主机隔离状态；在授权测试范围内验证网络限制、终端状态和平台回报 | 查询主机已解除隔离，并确认主机健康状态和业务连通性 |
| 失败处理 | 超时先查询主机状态；状态不明进入 `HUMAN_REQUIRED`；多主机结果分别记录 | 解隔离状态不明时保持人工处理，不重复执行 |
| 回滚/反向动作 | 解隔离属于反向动作，但必须关联原隔离记录 | 如恢复后仍有风险，重新发起隔离审批 |
| 人工接管 | 主机离线、身份冲突、核心业务资产、无法验证网络状态或部分成功时转人工 | 业务恢复异常、主机状态不一致或仍有未解决威胁时转人工 |

当前环境仅确认页面入口和产品材料，未确认可执行的 EDR/CWPP 主机资源。

### 5.6 文件处置、解除隔离与信任文件

| 动作 | 默认风险 | 执行策略 | 必要前置检查 | 独立验证 | 回滚/人工接管 |
| --- | --- | --- | --- | --- | --- |
| 文件处置/隔离 | `HIGH` | `APPROVAL_REQUIRED` | 主机唯一标识、文件路径、文件哈希、文件大小、文件来源、业务文件白名单和文件是否仍存在 | 查询处置记录；在终端侧核对文件状态、哈希和相关进程是否仍可访问 | 解除隔离需原记录和审批；哈希或路径不一致时转人工 |
| 文件解除隔离 | `HIGH` | `APPROVAL_REQUIRED` | 必须确认原文件隔离记录、恢复目标和业务恢复理由 | 查询文件已恢复，并核对文件哈希、路径和终端可见性 | 恢复后发现风险时停止自动流程，转人工重新隔离 |
| 信任文件 | `CRITICAL` | `HUMAN_ONLY` | 至少双人复核文件哈希、来源、签名、业务归属、误报证据和影响范围 | 查询信任规则，并在受控终端确认规则生效范围 | 移除信任只能处理本系统创建的记录；任何范围不明情况转人工 |
| 移除文件信任 | `HIGH` | `APPROVAL_REQUIRED` | 必须存在原信任记录和移除理由，确认不会影响业务启动 | 查询信任记录已移除，并观察后续检测结果 | 可能触发新的安全告警，需保留人工接管入口 |

文件动作不能只根据路径判断对象。最小对象标识建议至少包含 `host_id`、`file_path` 和 `file_hash` 中的两个，并将实际平台返回的对象 ID作为后续反向动作依据。

当前环境无可测 EDR/CWPP 文件资源，不能验证文件状态变化、终端证据或信任规则生效。

### 5.7 阻断进程与病毒扫描/查杀

| 项目 | 阻断进程 | 病毒扫描/查杀 |
| --- | --- | --- |
| 动作语义 | 阻止或终止指定主机上的进程 | 对主机或文件执行扫描，并按平台能力进行查杀或处置 |
| 默认风险 | `HIGH` | `HIGH`；仅查询或扫描而不删除时可按场景降为 `MEDIUM` |
| 执行策略 | `APPROVAL_REQUIRED` | 扫描可 `APPROVAL_REQUIRED`；自动查杀建议 `HUMAN_ONLY` |
| 前置检查 | 主机、进程名、进程 ID、进程哈希、父子进程关系、业务白名单和终止影响 | 样本哈希、主机、扫描范围、业务例外、隔离/删除策略和恢复条件 |
| 预期调用结果 | 返回进程或动作 ID、执行状态和目标主机 | 返回任务 ID、扫描范围、检测结果和处置状态 |
| 独立验证 | 查询进程状态和动作记录；在授权范围内确认进程未重新启动 | 查询任务结果、文件处置记录、检测状态和终端文件证据 |
| 失败处理 | 超时先查询进程/动作状态；不能依据单次失败自动重复终止 | 任务状态不明时不得重复启动可能产生副作用的查杀 |
| 回滚/反向动作 | 没有通用自动回滚；恢复进程需要业务侧或人工处理 | 删除/修复结果通常不可自动回滚，必须保留人工恢复路径 |
| 人工接管 | 进程属于核心服务、对象身份不唯一、无法验证终止效果或出现重启风暴 | 查杀影响业务、误报可能性高、文件不可恢复或结果部分成功 |

当前环境仅确认模板标签和页面入口，未确认真实 EDR/CWPP 执行能力；不能把“病毒查杀”模板存在写成查杀已经可用。

### 5.8 SOAR 预案、审批、工单和执行历史

这些能力主要承担流程控制和审计作用，不应被当作底层处置能力本身。

| 能力 | 安全控制设计 |
| --- | --- |
| 预案编排 | 预案只能调用白名单动作；动作参数需要结构化校验；高风险动作前必须存在人工审批节点 |
| 人工审批 | 审批对象应包含事件、证据、目标、风险、影响、有效期、验证方式和回滚方案；审批结果使用独立 `idempotency_key` |
| 待我处置 | 用于人工分析、审批、补充参数和人工接管；不能因为队列存在就推断动作已执行 |
| 流程工单 | 用于跨角色流转、补证、授权和人工处理；工单完成不等于技术动作生效 |
| 执行历史 | 记录请求、执行、重试、平台返回、验证和人工处理过程；至少关联 `trace_id`、`event_id`、动作 ID和幂等键 |
| 系统日志 | 用于审计登录、配置、审批、动作调用和状态调整；缺少处置操作日志时，相关动作证据应保持为未验证 |

## 六、低风险候选动作

以下动作适合作为当前 MVP 的低风险候选，前提是仍经过确定性规则、参数校验和审计：

| 候选动作 | 自动化边界 | 最小验证 | 不得自动化的情况 |
| --- | --- | --- | --- |
| 通知指定责任人或审批人 | 仅允许向配置白名单发送结构化通知 | 查询发送记录或通知审计 | 收件人不明、外部扩散、敏感信息未脱敏 |
| 创建工单并转人工 | 自动创建，不自动执行后续高风险动作 | 查询工单 ID、负责人和流转状态 | 工单目标不明、重复创建或无法关联原事件 |
| 查询处置状态 | 允许自动执行，只读 | 返回平台状态、执行历史或证据引用 | 查询接口权限不足、返回字段不完整 |
| 告警状态推进到 `triaged` 或 `investigating` | 仅限当前事件、单对象、确定性条件 | 重新读取对象状态并核对操作日志 | 推进到 `contained`/`closed`、目标范围不明、状态冲突 |
| 生成预案草案或处置建议 | 允许自动生成，但不触发真实动作 | 结构化字段校验和安全策略检查 | 模型输出无法解析、缺少目标或包含未授权动作 |

当前 MVP 可将这些低风险动作与 `stateful_response_mock` 结合，用于验证审批、幂等、失败、验证和人工接管流程；但 Mock 成功仍不能证明 XDR 真实动作可用。

## 七、统一执行与验证要求

### 7.1 执行前检查

每个真实或 Mock 处置请求至少应检查：

- `event_id`、目标对象和动作语义是否存在；
- 目标是否属于当前事件证据支持的范围；
- 目标是否命中资产、网络、文件或业务白名单；
- 动作风险等级是否与审批状态一致；
- 是否存在有效的 `idempotency_key`；
- 是否设置超时时间、最大尝试次数和有效期；
- 是否存在独立验证方法；
- 高风险动作是否存在回滚或明确人工恢复方案。

### 7.2 幂等、超时和重试

- 同一业务动作必须使用稳定的 `idempotency_key`，重复请求不得覆盖第一次执行记录。
- 超时不等于失败。对可能产生副作用的动作，必须先查询动作状态，再决定是否重试。
- 只有平台明确标记为可重试，且不会造成重复副作用时，才允许自动重试。
- 认证失败、权限不足、参数校验失败和不支持动作不应自动重试。
- 重试次数、每次结果和最终判断必须写入执行历史或审计记录。
- 当前代码中的 `timeout_seconds`、`max_attempts` 和幂等键已经存在于 `ToolRequest`，但真实平台超时和重试语义尚未验证。

### 7.3 失败和部分成功

建议统一映射：

| 情况 | 处理 |
| --- | --- |
| 参数或目标校验失败 | 不调用真实平台，返回结构化校验失败 |
| 鉴权/权限失败 | 不重试，进入 `HUMAN_REQUIRED` |
| 明确平台失败且无副作用 | 按 `retryable` 决定是否重试 |
| 超时且状态未知 | 先查询；仍无法确认则 `UNKNOWN` + `HUMAN_REQUIRED` |
| 多目标仅部分完成 | 保留逐目标结果，整体标记 `PARTIAL_SUCCESS`，禁止汇总为成功 |
| 调用成功但独立验证无效 | 进入 `HUMAN_REQUIRED`，不能自动宣称处置完成 |
| 验证接口不可用 | 处置结果保持未知，不能以调用结果替代生效证据 |

### 7.4 验证证据

独立验证至少应优先使用不同于执行响应的证据来源：

- 平台处置对象或执行历史状态；
- 目标主机、文件、进程或网络对象的实时状态；
- 专用测试目标上的受控行为验证；
- 操作日志、动作 ID、规则 ID和时间戳；
- 多目标动作的逐目标结果。

验证结果应写入 `VerificationResult`，并区分：

- `effective`：存在足够证据证明生效；
- `ineffective`：存在证据证明未生效；
- `unknown`：证据不足或平台不可查询。

## 八、禁止执行与强制人工接管边界

### 8.1 当前禁止自动执行

以下情形在当前 MVP 和当前 XDR 环境中禁止自动执行：

- 批量或全局 IP/域名封禁；
- 通配符域名、顶级域名或未知范围的域名拦截；
- 核心业务、域控、数据库等高价值资产的主机隔离；
- 未经双人复核的信任文件或全局白名单变更；
- 自动永久删除文件、不可恢复的查杀或无回滚动作；
- 未确认目标身份的进程终止；
- 在平台返回状态未知时重复发送可能产生副作用的请求；
- 仅凭模型建议、单条低置信度告警或页面入口存在直接触发真实动作；
- 尚未确认真实 API、权限、设备资源和返回语义时调用 XDR 真实处置接口。

### 8.2 强制转人工条件

满足任一条件时，流程应进入 `HUMAN_REQUIRED`：

- 目标命中白名单或业务例外；
- 审批被拒绝、审批信息不完整或审批与目标不匹配；
- 执行结果为 `PARTIAL_SUCCESS`；
- 超时后无法确认是否产生副作用；
- 执行记录与独立验证结果不一致；
- 目标、动作、设备或平台返回字段无法解析；
- 处置无可靠回滚路径；
- 需要调整事件终态但缺少独立验证；
- 平台资源不足、设备离线或账号权限不足；
- 当前安全状态或业务影响无法由系统确定。

## 九、与当前 MVP 的关系

当前代码中的最小处置闭环为：

```text
ResponsePlan
  -> APPROVAL_REQUIRED
  -> stateful_response_mock
  -> response_verify
  -> COMPLETED / HUMAN_REQUIRED / FAILED
```

当前 `ResponsePlan.action` 使用 `stateful_mock_containment`，这是统一工具契约下的有状态 Mock 动作。它可以验证：

- 审批前后状态流转；
- `idempotency_key` 的重复提交控制；
- 执行结果与独立验证的分离；
- 验证无效或未知时进入人工接管；
- `mode=mock` 的结果标记。

它不能证明：

- XDR 真实动作名称和参数已经确定；
- 当前账号可以调用真实处置接口；
- 真实设备资源已经接入；
- 平台返回的执行状态等于网络、主机或文件状态已生效。

因此，真实平台适配器后续应复用 `ToolRequest` / `ToolResult` 契约，并为每个动作补充白名单、参数校验、权限检查、超时处理、逐目标结果、独立验证和审计引用；不应通过把 `stateful_mock_containment` 改名为平台动作来掩盖真实接口尚未确认的问题。

## 十、待补充的 XDR 平台信息

为了将本表从“安全语义映射”推进到“平台调用映射”，后续最小需要补充：

1. `应用管理` 中 XDR 内置应用的动作列表详情，尤其是处置类动作的准确名称；
2. 预案模板中“封堵 IP”“封堵域名”“主机隔离”“文件处置”“病毒查杀”等动作的参数配置页；
3. `响应管理` 各页面的详情、操作按钮和结果提示；
4. `执行历史` 中单次动作详情的字段，包括动作 ID、目标、状态、错误、时间和结果；
5. `系统日志 -> 操作日志` 中一次低风险测试操作对应的日志字段；
6. 如平台存在，只需截图或导出只读说明即可确认 `dry-run`、审批、有效期、反向动作和验证入口；不需要发起真实封禁、隔离或查杀。

在未取得上述信息前，平台动作名、接口参数、返回字段、回滚字段和生效字段统一保持“待确认”。

## 十一、阶段性结论

本表完成了候选处置动作到安全控制要求的第一版映射：

- 低风险动作优先用于通知、工单、只读查询、有限状态推进和建议生成；
- 网络阻断、主机隔离、文件处置、进程阻断和病毒查杀默认需要人工审批；
- 信任文件、批量处置、通配符拦截和无可靠回滚动作禁止自动执行；
- 所有可能产生副作用的动作都必须区分调用成功、执行记录和实际生效；
- 超时、部分成功、状态未知和验证失败统一进入人工接管路径；
- 当前 XDR 证据只支持产品材料、页面入口、账号权限和部分资源状态，尚不支持真实处置调用或生效结论。

因此，当前阶段可提交的安全映射结论是：

> 候选动作及其风险、审批、验证、失败、回滚和人工接管边界已经形成第一版设计；真实平台动作名称、参数、设备资源和生效证据仍待 XDR 只读核对或授权的低风险最小验证。
