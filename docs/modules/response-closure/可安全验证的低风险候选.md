# 可安全验证的低风险候选

## 一、任务定位

本文档对应 `T0827-08 肖迎春：平台处置能力核验与 Mock 安全边界` 第三项任务，用于从《平台处置能力核验表》和《候选处置动作安全映射表》中筛选当前阶段可以安全核对或提出测试方案的低风险候选。

本任务的目标是：

- 优先验证只读查询、审计和流程辅助能力；
- 在不改变真实网络、主机、文件和进程安全状态的前提下，验证工具调用边界；
- 为确需写入的平台动作规定测试对象、权限、停止条件和证据要求；
- 为当前 MVP 的有状态 Mock 闭环提供可重复的验证场景。

本文档不授权任何真实封禁、解封、隔离、解隔离、文件处置、查杀、进程阻断或信任文件操作。没有满足前置条件时，候选动作只保留为建议测试方案。

## 二、当前可用条件与限制

### 2.1 已确认条件

- 当前 XDR 账号为 `admin` 超级管理员，相关菜单和处置入口可见。
- 当前 XDR 环境可以读取真实告警、安全事件和原始日志。
- `威胁响应 -> 预案中心`、流程工单、执行历史、系统日志和应用管理入口存在。
- XDR 内置应用实例存在，当前记录的应用版本为 `1.0.104`。
- 当前代码存在 `xdr_log_query`、`evidence_lookup` 和 `response_verify` 等只读或验证相关工具路径。
- 当前代码存在有状态 Mock 处置账本，可使用 `stateful_response_mock` 和 `query_action_status` 验证幂等、执行记录和独立验证。

### 2.2 当前限制

- 当前没有已确认的真实处置 API 请求、返回字段、错误码或生效查询记录。
- 当前没有足够的 EDR、CWPP、AF 或其他真实处置设备资源用于隔离、封禁、文件和进程动作验证。
- XDR 页面入口、模板或内置动作存在，不等于当前账号已经能够通过接口完成真实动作。
- 当前不能把平台调用成功、执行历史有记录或 Mock 状态为 `executed` 直接解释为真实安全状态已经改变。
- 当前不具备执行真实高风险写操作的授权依据。

## 三、候选分级

| 级别 | 适用范围 | 当前建议 |
| --- | --- | --- |
| `L0` | 只读查询、页面核对、代码内 Mock 验证，不改变 XDR 业务或安全状态 | 当前可直接验证 |
| `L1` | 仅改变通知、工单或草稿等辅助状态，不改变网络、主机、文件和进程安全状态 | 具备明确对象和范围后，可申请最小验证 |
| `L2` | 改变告警/事件流程状态，可能影响平台后续编排，但不直接改变设备安全状态 | 只允许测试对象或专门演示环境 |
| `禁止项` | 真实封禁、隔离、文件处置、查杀、进程阻断、信任文件和解封/恢复动作 | 当前不验证，只提交方案 |

排序原则：

1. 先验证不产生外部副作用的读取和查询；
2. 再验证可审计、可控范围的通知和工单；
3. 只有测试对象明确、预案未启用、动作可回退时，才考虑流程状态写入；
4. 不因为动作名称出现在模板或页面中，就发起真实安全写操作。

## 五、当前可以直接验证的 L0 候选

### 5.1 查询告警和安全事件详情

#### 验证目标

确认当前账号能够读取真实告警或安全事件，并能获得后续处置决策所需的最小字段。

#### 建议入口

- XDR 告警列表或告警详情；
- XDR 安全事件列表或安全事件详情；
- 项目已有的 XDR 查询工具或只读适配器。

#### 最小字段

- 告警/事件 ID；
- 名称、类型、风险等级和时间；
- 来源设备；
- 源/目的 IP、端口和协议；
- 影响资产；
- 当前处置状态；
- 关联告警；
- 原始证据或日志引用。

#### 安全边界

- 只打开详情或发起查询；
- 不点击封禁、隔离、处置、解封、查杀和状态调整按钮；
- 不执行页面中可能触发预案的“立即处置”“执行预案”等操作；
- 查询结果中出现真实 IP、资产或账号信息时，截图前进行必要脱敏。

#### 验收证据

至少保存一张包含查询条件和结果字段的截图，或保留只读接口返回摘要。证据中应能看出查询时间、目标对象和返回结果，但不要求出现任何处置成功记录。

#### 预期结论

`账号有权限读取真实告警/事件`，不延伸为`账号有权限执行真实处置`。

### 5.2 查询 STA/XDR 原始日志和证据引用

#### 验证目标

确认已验证的 STA -> XDR 原始日志链路可以为处置建议提供证据引用，并验证查询结果仍然是只读。

#### 建议入口

- XDR 原始日志或网络安全日志查询；
- 已确认的 STA 来源 SQL 注入日志；
- 项目中的 `xdr_log_query` 或证据查询工具。

#### 建议查询条件

- 已知时间窗口；
- STA 来源设备；
- 已知规则名称；
- 已知源/目的 IP；
- 已知事件或告警关联条件。

#### 验收证据

- 查询条件；
- 返回记录数量；
- 规则或名称；
- 时间；
- 源/目的地址；
- 原始日志引用或平台记录 ID；
- 查询无写操作的说明。

#### 预期结论

可以确认调查证据可读、可引用、可复核；不能据此确认任何网络阻断动作已经执行。

### 5.3 查询处置对象、动作历史和执行历史

#### 验证目标

确认平台提供处置记录和执行回溯入口，并观察当前环境是否有记录。

#### 建议入口

- `威胁响应 -> 响应管理` 下的处置对象列表；
- `威胁响应 -> 预案中心 -> 执行历史`；
- 动作执行历史或详情；
- 必要时按时间、事件 ID、动作或执行人筛选。

#### 安全边界

- 只查询、筛选、展开详情和导出只读结果；
- 不点击重试、执行、解封、解除隔离或删除记录；
- 当前列表为空属于有效验证结果，不需要为了产生数据而发起真实处置。

#### 验收证据

- 页面入口；
- 查询条件；
- 空列表或已有记录；
- 可见字段名称；
- 若存在记录，记录中的状态、执行人、时间、目标和动作 ID；
- 截图中不得暴露敏感令牌或完整凭据。

#### 预期结论

可以确认平台提供执行回溯能力；若列表为空，只能结论为`入口存在但当前无执行证据`。

### 5.4 查询系统/操作日志

#### 验证目标

确认平台具备审计入口，并识别处置调用后需要记录的字段。

#### 建议入口

`配置管理 -> 系统监控 -> 系统日志 -> 操作日志`

#### 当前已知情况

现有核验表记录当前主要看到登录日志，尚未看到处置操作日志。因此该候选适合直接只读核对，但不能为了制造处置日志而发起高风险动作。

#### 重点观察字段

- 操作时间；
- 操作用户；
- 来源 IP；
- 操作类型；
- 操作对象；
- 操作结果；
- 关联任务、动作或请求 ID。

#### 预期结论

可以确认日志字段和审计入口；没有处置日志时，任何真实处置调用仍保持为未验证。

### 5.5 查询应用实例和动作目录

#### 验证目标

确认 XDR 内置应用的实例状态、版本和动作目录，补齐后续真实适配器需要的只读信息。

#### 建议入口

`威胁响应 -> 预案中心 -> 应用管理 -> 深信服XDR可扩展检测响应平台`

#### 只读观察项

- 应用实例名称和版本；
- 实例接入状态；
- 动作总数；
- 动作准确名称；
- 动作说明；
- 参数字段和是否必填；
- 是否存在测试按钮；
- 是否存在 dry-run、预览或审批配置；
- 是否能看到动作返回字段或结果示例。

#### 特别注意

页面中的“测试”“编辑”“删除”按钮不自动等同于安全的只读操作。除非能确认测试按钮只执行查询或预览，否则只截图按钮和说明，不点击执行。

#### 预期结论

可以补充真实动作名称和参数候选，但仍不能确认真实动作执行、生效或回滚能力。

### 5.6 本地结构化处置建议和安全策略检查

该候选不需要操作 XDR，可在项目本地完成：

- 使用调查报告生成 `ResponsePlan`；
- 检查目标、风险等级、审批要求和回滚可用性；
- 检查不支持动作是否被拦截；
- 检查高风险动作是否进入 `APPROVAL_REQUIRED`；
- 检查缺少目标或缺少调查结论时是否不生成处置计划；
- 检查模型输出是否经过结构化字段校验。

当前代码中已有的关键字段包括：

```text
ResponsePlan.action
ResponsePlan.target
ResponsePlan.risk_level
ResponsePlan.approval_required
ResponsePlan.rollback_available
```

该候选的证据来自本地测试和结构化输出，不应写成 XDR 平台真实处置证据。

### 5.7 有状态 Mock 执行与独立验证

#### 验证目标

在不接触真实设备的情况下，验证处置闭环的审批、幂等、执行、验证和人工接管路径。

#### 推荐链路

```text
ResponsePlan
  -> APPROVAL_REQUIRED
  -> stateful_response_mock
  -> response_verify
  -> COMPLETED / HUMAN_REQUIRED / FAILED
```

#### 最小场景

| 场景 | 预期结果 |
| --- | --- |
| 审批通过 | 执行 Mock 处置，随后进入独立验证 |
| 审批拒绝 | 进入 `HUMAN_REQUIRED`，不执行处置 |
| 相同幂等键重复审批 | 不重复推进执行、验证和完成状态 |
| Mock 执行成功 | `ExecutionResult.mode=mock`，不代表真实平台成功 |
| 找不到 Mock 处置记录 | 验证状态为 `unknown`，进入人工接管 |
| Mock 执行失败 | 进入 `FAILED`，不直接继续验证 |

#### 验收证据

- 审批前后的状态时间线；
- `ToolRequest.idempotency_key`；
- `ToolResult.status`、`side_effect_type` 和 `mode`；
- `VerificationResult.status`；
- 最终业务状态；
- 明确标注数据来源为固定样例、JSONL 样例或进程内 Mock。

## 六、条件性 L1 候选

### 6.1 向自有内部邮箱发送测试通知

#### 适用条件

只有在以下条件全部满足时，才可以申请最小验证：

- 收件人是操作者本人或已授权的内部测试邮箱；
- 邮件内容不含未脱敏的真实账号、密钥、完整日志和不必要的个人信息；
- 发送动作不会触发后续自动预案；
- 发送频率和数量固定为单封；
- 能够查询发送记录或操作日志。

#### 测试方案

1. 使用一条固定样例或专门演示事件；
2. 通知主题明确标记为测试；
3. 收件人只填写自有内部地址；
4. 内容只包含事件摘要、风险级别、证据引用和“未执行真实处置”的说明；
5. 发送后查询通知记录或操作日志；
6. 若没有发送记录，结论保持为“请求结果未验证送达”。

#### 停止条件

- 收件人无法确认；
- 页面存在自动执行或联动选项；
- 通知内容无法脱敏；
- 发送按钮会触发预案或其他动作；
- 出现批量发送、外部地址或未知模板变量。

### 6.2 创建内部流程工单并转人工

#### 适用条件

工单不会改变网络、主机、文件或进程状态，适合作为人工接管链路的低风险候选。但仍会改变平台业务数据，因此必须使用测试事件或明确授权的演示事件。

#### 测试方案

1. 选择固定样例或专门演示事件，禁止直接修改真实生产事件；
2. 工单标题标记为“测试/演示”；
3. 描述中写明：不执行真实封禁、隔离、查杀等动作；
4. 指定一名明确的内部负责人；
5. 创建工单后只验证工单 ID、负责人、状态和流转记录；
6. 测试结束后按平台提供的关闭或归档流程处理，不删除审计记录。

#### 预期结论

可以证明人工接管队列和工单关联能力，不代表下游真实处置能力可用。

#### 停止条件

- 创建工单会自动触发预案；
- 工单对象无法关联事件；
- 工单字段要求填写未经确认的真实处置参数；
- 不能区分测试工单和真实工单；
- 创建后无法查询负责人或流转记录。

### 6.3 保存禁用状态的预案草稿

该候选只用于核对预案节点、参数和审批结构，风险高于纯只读查询。

#### 必须先确认

- 草稿保存不会自动启用；
- 预案没有自动触发条件；
- 预案不会调用真实封禁、隔离、查杀或其他设备动作；
- 所有高风险动作节点处于未连接、模拟或审批阻断状态；
- 可以查询草稿 ID、启用状态和节点配置。

#### 建议内容

只保存以下类型的草稿：

- 告警/事件查询；
- 证据汇总；
- 通知草稿；
- 人工审批节点；
- 工单创建节点；
- 结束节点。

不建议在当前环境保存包含真实处置节点的可执行预案，即使预案当前显示为未启用。

## 七、仅限测试对象的 L2 候选

### 7.1 告警状态推进到 `triaged`

该动作不直接改变设备安全状态，但会改变 XDR 的流程状态，可能影响后续展示、统计或自动编排，因此不能作为无条件低风险动作。

#### 只有以下条件全部满足时才可验证

- 平台提供明确的测试告警或专门演示对象；
- 对象不是当前真实生产告警；
- 已确认 `new -> triaged` 是允许的状态转移；
- 已确认不会触发自动处置预案；
- 能记录调整前状态、调整后状态、操作人和操作日志；
- 已确认存在可审计的反向流程或人工恢复方式。

#### 测试方案

1. 记录测试对象 ID和调整前状态；
2. 只调整单个对象；
3. 记录操作人、时间和页面/接口返回；
4. 重新查询对象状态；
5. 查询操作日志；
6. 如状态未持久化或出现其他联动，立即转人工。

### 7.2 告警状态推进到 `investigating`

控制要求与 `triaged` 相同，但应额外确认：

- 状态是否会触发深度调查或 SOAR 预案；
- 是否会覆盖其他人员正在进行的调查；
- 状态推进是否需要填写调查人或调查理由；
- 是否存在并发编辑冲突。

当前没有专门测试对象时，不建议在真实告警上执行状态调整。可以只记录页面入口、字段和按钮，不点击提交。

## 八、禁止作为当前低风险验证的动作

以下动作即使页面入口、产品材料或模板已经存在，也不属于当前可直接验证的低风险候选：

- IP 封禁、解封或批量封禁；
- 域名拦截、解除拦截、通配符拦截；
- 主机隔离、解隔离；
- 文件隔离、解除隔离、删除或恢复；
- 信任文件、移除信任或修改全局白名单；
- 阻断进程、终止进程或自动重启相关动作；
- 病毒查杀、不可恢复删除和大范围扫描；
- 未确认范围的告警/事件终态关闭；
- 从预案模板直接启动可能包含真实处置动作的预案；
- 点击无法确认语义的“测试”“执行”“重试”“立即处置”按钮。

这些动作后续如需验证，至少要另行具备：

- 已授权的测试设备或隔离实验环境；
- 明确的目标范围和恢复方案；
- 已确认的调用对象、参数和返回字段；
- 独立验证方法；
- 回滚或人工恢复安排；
- 负责人对真实写操作的明确授权。

## 九、统一安全验证流程

### 9.1 验证前

- 确认操作属于 `L0`、`L1` 或已批准的 `L2`；
- 确认对象是固定样例、测试对象或明确授权的演示对象；
- 记录当前页面、对象 ID、时间和账号；
- 确认无自动预案、批量范围和隐含联动；
- 准备停止条件和人工接管联系人；
- 对截图和导出结果做必要脱敏。

### 9.2 验证中

- 一次只验证一个能力；
- 优先读取结果，不连续点击多个动作；
- 保留请求条件、页面返回和操作日志；
- 发现状态不明、范围扩大或按钮语义不清时立即停止；
- 不用“页面没有报错”代替成功证据。

### 9.3 验证后

- 重新查询对象、历史和日志；
- 记录“已读取”“已提交请求”“已产生记录”“已生效”分别对应的证据；
- 对 L1/L2 写操作确认测试对象没有进入真实自动处置链路；
- 对未能独立验证的结果标记为 `unknown`；
- 形成“产品材料存在、页面入口存在、当前环境未验证”等结论，不扩大解释。

## 十、证据记录模板

每个候选建议按以下字段记录：

| 字段 | 内容 |
| --- | --- |
| 候选 ID | 例如 `L0-03` |
| 验证日期 | 使用绝对日期和时间 |
| 操作账号 | 账号名称或脱敏标识 |
| 平台入口 | 页面路径或工具语义 |
| 对象 | 固定样例、测试事件或查询条件 |
| 是否写操作 | `否`、`是-辅助状态`、`是-流程状态` |
| 是否触发真实安全状态变化 | `否` / `未知` / `是` |
| 请求/页面结果 | 原文摘要或脱敏截图引用 |
| 独立证据 | 日志、历史、二次查询或本地测试结果 |
| 最终结论 | 已验证、部分验证、未知、人工接管 |
| 剩余问题 | API 名称、权限、字段、设备或生效证据 |

推荐结论用语：

- `产品材料存在，页面入口存在，当前环境可只读验证。`
- `页面入口存在，当前无业务数据，未形成真实执行证据。`
- `辅助状态写入可在测试对象上验证，不能外推到真实处置能力。`
- `Mock 闭环已验证，不代表真实平台动作已执行或生效。`
- `平台动作和权限尚未确认，仅提交建议测试方案。`

## 十一、阶段性结论

当前最适合验证的候选是：

1. 告警/安全事件详情查询；
2. STA/XDR 原始日志和证据查询；
3. 处置对象、动作历史、执行历史查询；
4. 系统/操作日志查询；
5. XDR 应用实例和动作目录只读核对；
6. 本地结构化处置建议和安全策略检查；
7. 有状态 Mock 执行、独立验证、幂等和人工接管测试。

在获得明确测试对象和授权前，通知、工单、预案草稿和告警状态调整只提交条件性方案，不直接操作当前真实环境。IP/域名封禁、主机隔离、文件处置、信任文件、进程阻断和病毒查杀继续保持禁止验证状态。

因此，目前提交结论为：

> 当前阶段可以安全验证只读查询、审计、动作目录、结构化建议和有状态 Mock 闭环；通知和工单可作为受控辅助动作候选，流程状态调整仅限测试对象；所有真实安全状态写操作仍未授权、未验证，不得由页面入口、模板存在或 Mock 成功推导为真实平台能力。
