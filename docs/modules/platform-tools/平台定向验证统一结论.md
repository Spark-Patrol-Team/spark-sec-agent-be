# 平台定向验证统一结论

## 一、统一结论

本轮平台定向验证已形成以下统一结论：

1. **XDR 真实数据可用。** 已确认当前环境能够读取真实告警、安全事件和原始日志；可获取告警/事件时间、规则或名称、风险等级、来源设备、源/目的 IP 与端口、影响资产、关联告警及处置状态等调查信息。
2. **STA-XDR 原始日志链路已打通且具有可重复性。** STA 的“分布式 XDR/XDR 前置机”通道接入正常，XDR 已识别 STA 设备并持续接收日志。单文件回放和五文件补测均成功触发 STA 检测，并在 XDR 中形成可检索的 SQL 注入相关日志，证明“STA 回放 → STA 检测 → XDR 原始日志上报”链路可正常使用。
3. **告警/事件聚合仍需继续核查。** 当前尚未确认每轮回放都会自动生成一条可与该轮任务逐一关联的新告警或安全事件。该问题不影响原始日志链路成立，但第一版不能把“每轮必然新增安全事件”作为前置条件或对外承诺。
4. **平台验证小组建议采用，待钱诺成确认**。 该场景已经过两轮真实链路验证，可稳定展示回放、检测、日志上报、风险研判、深度调查和处置建议。STA 来源内网横向行为可作为补充真实场景；WebShell 保留为高危固定样例或进阶演示，不再作为当前真实回放主链的必选项。
5. **OpenAPI、MCP 和安全 GPT 的平台能力范围基本明确，但外部调用尚未完成实机闭环。** OpenAPI 文档、接口目录和鉴权方式已确认；MCP 与安全 GPT 的工具类型、调查能力和使用方式已从材料中确认，但当前仍缺实际 OpenAPI 调用记录、MCP `tools/list` 结果及安全 GPT 外部调用返回，因此暂不能写成“已稳定接入”。
6. **固定告警输入和降级链路已具备开发条件。** 已完成 3 条原始样例、3 条标准化样例、最小字段契约、字段映射、JSON Schema 和测试用例索引，可直接用于解析器、风险研判、深度调查、处置闭环、前端展示和回归测试。

## 三、实测结果与证据边界

### 3.1 STA-XDR 链路实测结果

- STA 侧“分布式 XDR/XDR 前置机”显示接入正常。
- XDR 侧已识别 STA 设备在线，并显示日志上报与联动/处置状态。
- 单文件回放成功后：
  - STA 当日日志总数由 6 增至 42；
  - 网络安全日志由 4 增至 28；
  - HTTP 协议审计日志由 1 增至 7；
  - XDR 中出现对应时间窗口的 STA 来源 SQL 注入规则命中。
- 五文件补测成功后：
  - STA 当日日志总数由 42 增至 119；
  - 网络安全日志由 28 增至 77；
  - HTTP 协议审计日志由 7 增至 21；
  - 网络安全日志检索结果由 77 增至 140；
  - 新增记录包含“通用 SQL 注入攻击”“Select 语句 SQL 注入攻击”“元数据查询语句 SQL 注入攻击”等规则命中。

上述结果足以确认回放执行、STA 检测和 XDR 原始日志同步具备可重复性。当前只需继续核查事件生成规则、聚合阈值、时间窗口、筛选条件及聚合延迟，不需要再通过无目标增加回放文件来证明基础链路。



## 四、深度调查可用数据与工具需求

深度调查模块可围绕以下信息组织输入与输出：

- **告警与事件：** 告警/事件 ID、名称、类型、等级、时间、来源设备、定性、状态及关联告警。
- **网络与资产：** 源/目的 IP、端口、协议、影响资产、资产状态及同源/同目的活动。
- **原始证据：** STA 网络安全日志、HTTP 审计日志、规则命中、攻击状态及原始日志引用。
- **关联调查：** 威胁实体、影响面、相似/高频告警、关系溯源、攻击故事线；接入 EDR 后还可补充主机、进程和进程链。
- **安全 GPT：** 告警/事件解读、威胁实体调查、攻击定性、处置建议和引导式调查。

第一版深度调查 Agent 应先基于已确认的真实日志字段完成证据整理、缺口识别、调查计划和报告生成；平台工具调用采用可插拔方式接入。若 MCP 或安全 GPT 暂不可用，调查主流程必须能够继续使用 OpenAPI、固定样例或人工补充证据运行。
